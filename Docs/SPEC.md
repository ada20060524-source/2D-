# 直向卷軸射擊遊戲 分階段開發規格書 (SPEC.md)

本規格書依據《遊戲開發企劃規格書（直向卷軸射擊遊戲）》之核心機制、系統架構與 UI 配置編製，專供 Google Antigravity IDE 的 AI Agent 讀取與執行分階段開發任務。開發過程採嚴格迭代遞進導向，確保各階段任務皆經過 AI 自動驗證與開發者手動驗收後，方可推進至下一階段。

---

## 1. 專案全域架構與規範

在啟動任何階段的實作前，開發團隊與 AI Agent 必須遵守以下基礎設定：

* **畫面視口與渲染管線**：鎖定直向比例 9:16（標準基準解析度 1080 x 1920），主攝影機（Main Camera）採正交視角（Orthographic），固定視口範圍作為遊戲安全邊界。
* **物理圖層規劃（Physics 2D Layers）**：劃分 `Player`、`PlayerBullet`、`Enemy`、`EnemyBullet` 與 `Item` 共五個碰撞圖層，關閉同陣營與無效物件之間的物理碰撞偵測。
* **極簡邊緣化 UI 佈局**：維持中央戰鬥區域視野淨空，將 UI 分配至 Top-Left (玩家 HP/護盾)、Top-Center (Boss 血條)、Top-Right (得分/最高分/暫停按鈕)、Center (動態 Warning/關卡橫幅)、Bottom-Left (保命炸彈/火力等級) 及 Overlay (暫停/結算面板)。

---

## 2. 階段 1：最基礎的核心互動與畫面渲染（最小可行性原型 MVP）

本階段目標為建構最基礎的遊戲控制迴圈、物件池與畫面渲染，完成最小可行性原型（MVP）。

### 【實作任務】

1. **畫面視口與三層視差捲動背景原型**：
   * 建立 9:16 正交視角畫布與固定視口邊界。
   * 實作無縫循環向下捲動背景，包含「遠景底層（星空/雲海）」、「中景裝飾（浮島/建築）」與「近景元素（高速雲層/碎片）」三層不同速率之捲動效果。
2. **玩家控制與核心判定區（Hitbox）**：
   * 實作玩家機體 8 方向平滑移動控制，並加入螢幕視口邊界限制（Clamp），防止機體移出畫面。
   * 採用「視覺大、判定小」機制：玩家機體 Sprite 保持正常視覺大小，但實際受擊 Hitbox 僅集中於機體核心點，並在核心位置繪製微型視覺提示點。
3. **基礎射擊與物件池管理（Object Pooling）**：
   * 支援長按連續發射預設單發直向玩家子彈（PlayerBullet）。
   * 建立物件池（Object Pool）機制：子彈飛出視口上方邊界或擊中敵人時立即停用回收，防止記憶體碎片化與卡頓。
4. **基礎 Enemy 敵人與觸發式碰撞**：
   * 實作基礎雜兵（Enemy）直線或定點進場。
   * 使用 Trigger 觸發器偵測 `PlayerBullet` 與 `Enemy` 碰撞，碰撞時扣除 Enemy 血量並回收子彈。
5. **極簡邊緣化 MVP UI 畫面**：
   * **左上角（Top-Left）**：顯示玩家目前剩餘生命值（HP）數值與殘機圖示。
   * **右上角（Top-Right）**：使用等寬字體（Monospace）即時更新顯示當前得分（Score）。

### 【AI 自動驗證標準】

Antigravity IDE 的 Agent 在內建瀏覽器環境中執行自動化測試時，必須檢查並通過以下條件：

* **移動與邊界限制測試**：模擬全方向輸入，驗證 Player 座標即時更新且嚴格限制於安全視口範圍內，無溢出邊界現象。
* **連射與物件池回收測試**：長按發射鍵 5 秒，驗證子彈生成與回收機制正常，超出視口上邊界的子彈 `active` 狀態被重置並回收到佇列，無無效物件累積。
* **碰撞與分數更新測試**：生成 PlayerBullet 與 Enemy 重疊，驗證 Trigger 觸發事件正確執行、Enemy HP 減少，且右上角 Score 數值正確加算。

### 【開發者手動驗收標準】

開發者於瀏覽器中操作測試之檢查清單：

* 按下方向鍵或 W/A/S/D 時，玩家機體是否能平滑向 8 個方向移動？移至畫面邊緣時是否會被擋住而不會飛出螢幕外？
* 玩家機體中央是否有一個清晰可見的小點（Hitbox 提示點）？
* 長按射擊鍵（如空白鍵）時，子彈是否會以穩定間隔持續向上發射？
* 子彈擊中飛入的敵人時，敵人是否會受擊扣血？右上角的分數是否會增加？

## 3. 階段 2：完整核心功能與進階操作邏輯擴充

本階段旨在導入動態關卡排程、彈幕擴充、武器升級與完整遊戲狀態迴圈。

### 【實作任務】

1. **關卡波次排程系統（Wave System）**：
   * 實作以時間軸為基準之關卡控制器：
     * **0–30 秒**：前期雜兵試探波次。
     * **30–60 秒**：中段精英怪進場與道具補給。
     * **60–90 秒**：高密度敵機陣型與彈幕壓力測試。
     * **90 秒後**：關卡 Boss 戰觸發。
   * 將敵人數量、進場路徑與隊形排列獨立封裝為資料驅動（Data-driven）之關卡配置檔。
2. **敵機子彈（EnemyBullet）與進階彈幕系統**：
   * 啟用 `EnemyBullet` 圖層，實作敵機自瞄或散射彈幕發射 logic。
   * 敵機子彈同樣納入物件池回收管理，超出視口自動停用。
3. **武器升級與 Power-Up 道具系統**：
   * 啟用 `Item` 圖層；擊破精英怪後掉落 Power-Up 道具並緩慢往下飄落。
   * 玩家 Hitbox 觸發拾取後，解鎖並升級散射（Spread）、雷射（Laser）或追蹤副武器。
4. **視覺受傷回饋與戰鬥演繹**：
   * **玩家受擊**：觸發無敵時間（Invincibility Time），機體伴隨高頻閃爍視覺回饋，並扣除生命值或降級火力。
   * **敵人與 Boss 受擊**：受擊時觸發瞬間「受擊閃白（Hit Flash）」效果；血量歸零時播放爆炸特效、音效與分數結算。
5. **完整遊戲狀態迴圈與 UI 佈局擴充**：
   * 實作狀態機（State Machine）：`Title` ➔ `Playing` ➔ `Warning` ➔ `Paused` ➔ `Victory / Game Over`。
   * **上方中央（Top-Center）**：顯示 Boss 長條血條，支援綠➔黃➔紅多階段顏色變化。
   * **中央區域（Center）**：Boss 登場前短暫浮現半透明動態 `WARNING` 標誌與關卡橫幅，演出後自動淡出。
   * **左下角（Bottom-Left）**：顯示保命炸彈（Bomb）數量與當前火力等級（Power）。
   * **全螢幕覆蓋層（Overlay）**：實作暫停面板與結算面板（含總得分、擊墜數、最高連擊數與重新開始/主選單按鈕）。

### 【AI 自動驗證標準】

Antigravity IDE 的 Agent 必須通過以下自動化檢測：

* **波次時間軸與 Boss 轉場測試**：加速模擬時間進程，驗證 0–90 秒內波次按時生成；90 秒時自動切換至 `Warning` 狀態並開啟 Boss 血條 UI。
* **受擊無敵與閃爍測試**：強制 EnemyBullet 與 Player 碰撞，驗證 Player 進入無敵狀態（判定暫時無效）且 Sprite 透明度呈週期性閃爍，無敵時間結束後恢復常態。
* **Boss 多階段血條連動測試**：持續對 Boss 造成傷害，驗證 Boss 血條依序由綠轉黃、由黃轉紅，當 HP 為 0 時觸發 Victory 結算 Overlay 面板。
* **狀態機切換與重置測試**：點擊 Pause 驗證遊戲暫停與面板彈出；於 Game Over 面板點擊 Restart，驗證物件池、玩家 HP、分數與時間軸完整重置。

### 【開發者手動驗收標準】

開發者於瀏覽器中操作測試之檢查清單：

* 隨著遊戲時間推移，出現的敵人數量與彈幕密度是否逐漸增加？90 秒時是否有動態 WARNING 警告與 Boss 登場？
* 擊破精英怪掉落道具後，操控機體吃掉道具，子彈是否會升級成散射或雷射？
* 玩家撞到敵機子彈時，機體是否會閃爍且暫時不會連續扣血（無敵時間）？
* 敵人被擊中時是否有閃白反饋？被擊破時是否有爆炸效果？
* 點擊右上角暫停鍵時，遊戲是否會暫停？Game Over 或勝利時是否有結算畫面顯示總分與重新開始按鈕？

## 4. 階段 3：本機資料持久化（讀寫/更新）、檔案匯入匯出與專案完整收尾

本階段重點為資料持久化、自訂關卡與存檔之匯入匯出機制，以及專案終極整合與記憶體管理。

### 【實作任務】

1. **本機資料持久化機制 (Local Data Persistence)**：
   * 整合 `localStorage` 或 `IndexedDB` 存取 API。
   * 實作最高分數（High Score）、遊戲設定（音量/開關）與解鎖紀錄之自動寫入與載入。
2. **關卡與存檔之檔案匯入與匯出 (File Import / Export)**：
   * **關卡檔匯入**：提供 UI 介面允許選擇並讀取 JSON 格式之自訂關卡波次配置檔（Wave Config），解析後動態套用新關卡排程。
   * **玩家存檔匯出與匯入**：支援將當前玩家最高分與成就數據導出為 `save_data.json` 檔案；並提供匯入檔案更新本機紀錄之功能。
3. **物件池與記憶體完整重置驗證**：
   * 確保進行多輪「重新開始」或「載入存檔」後，物件池中隱藏之無效物件被完全清空或重置，防止記憶體洩漏與重複事件監聽。
4. **專案整合與最終品質調校**：
   * 完善背景音樂（BGM）與打擊音效（SFX）之音訊管道控制。
   * 優化 9:16 直向視口在不同螢幕比例下的自適應居中縮放與黑邊（Letterboxing）處理。

### 【AI 自動驗證標準】

Antigravity IDE 的 Agent 必須通過以下自動化檢測：

* **持久化讀寫測試**：觸發 Game Over 並更新最高分紀錄，刷新瀏覽器頁面，驗證 High Score 仍保留上次最高數值。
* **JSON 檔案匯入解析測試**：模擬上傳合法 JSON 關卡配置檔，驗證 Wave System 成功載入新波次參數且無語法錯誤。
* **存檔匯出檔格式測試**：觸發匯出功能，檢查下載檔之 JSON 結構，確認包含 `highScore` 與 `settings` 欄位且資料型態無誤。
* **記憶體洩漏與池清空測試**：執行 10 次連續 Game Over/Restart 迴圈，檢查 DOM 節點數量與記憶體 Object Pool 總數保持恆定，無無效物件殘留。

### 【開發者手動驗收標準】

開發者於瀏覽器中操作測試之檢查清單：

* 打破最高分紀錄後關閉並重新開啟瀏覽器頁面，最高分紀錄（High Score）是否依然保存？
* 點擊「匯出紀錄」按鈕，是否能順利下載包含遊戲數據的 JSON 檔案？
* 上傳自訂的關卡 JSON 配置檔後，遊戲是否能依照新的敵人波次進行遊玩？
* 連續點擊重新開始遊戲多次，遊戲運作是否依然順暢、無卡頓或子彈殘留現象？

## 5. 【執行指引】（Execution Directives）

⚠️ **重要執行約束與開發順序原則**：

1. **嚴格禁止一次性完成所有階段**：Google Antigravity IDE 的 Agent 在執行本規格書時，**每次僅能針對當前單一階段**進行代碼撰寫與單元構建。
2. **階段性驗證與確認**：每完成一個階段的實作，Agent 必須先自動執行該階段的【AI 自動驗證標準】。驗證通過後，提示開發者進行【開發者手動驗收標準】之審查。
3. **明確推進條件**：**必須待開發者明確回覆確認無誤後，Agent 才可獲准進入下一個階段的開發工作**。若測試不通過或開發者提出修改意見，Agent 必須在當前階段持續修正至完全符合驗收標準為止。
